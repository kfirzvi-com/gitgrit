{# PostHog web analytics (Material's "custom" analytics provider, enabled by extra.analytics in mkdocs.yml), with a consent banner for cookies. - Consent (partials/consent.html is the banner): cookieless until the visitor accepts. cookieless_mode "on_reject" plus opt_out_capturing_by_default: a visitor with no choice, or one who rejected, is counted with a server-side hash of IP + user agent and a salt that rotates daily; nothing analytics-related is stored in the browser. "Accept" calls opt_in_capturing(): PostHog then sets its ph__posthog cookie (365 days, this host only) and session replay starts, with every input masked. "Reject" calls opt_out_capturing(). Needs "cookieless tracking" enabled in the PostHog project's Web analytics settings, or PostHog drops the cookieless events. - The choice is ours to remember: gg_consent in localStorage holds {v, choice, at}. It is void after 365 days or when consent_version in mkdocs.yml changes (bump it whenever legal/cookies.md changes what we set), and the banner asks again. If PostHog still holds an old opt-in then, we opt out first, so the cookie goes until the visitor accepts again. "Cookie settings" in the footer reopens the banner. - Never call identify(): visitors stay anonymous even with a cookie. - Production only: runs on gitgrit.dev, not staging or local mkdocs serve. before_send is a second guard and drops every event unless the hostname is still that host, so nothing is sent from localhost, 127.0.0.1, staging, or www. Off production the banner never shows. - api_host is PostHog's managed reverse proxy on our own subdomain (extra.analytics.api_host), so tracker blocklists don't drop the events. The loader fetches the SDK from /static/array.js. - Named events sit alongside autocapture (contact_clicked, app_clicked, get_started_clicked, github_clicked, demo_clicked). demo_booked fires from the Cal.com embed (partials/cal-embed.html) when a booking completes. - Pricing page (docs/pricing.md): every CTA click above also carries `plan` (free / team / business / enterprise, from data-plan), `billing_period` (monthly / annual) and `currency` (usd / eur; European time zones start on eur). Plus pricing_period_toggled {period}, pricing_currency_toggled {currency}, and pricing_section_viewed {section} once per section per page load: plans, enterprise, faq, and each FAQ question (faq:). Scroll depth and time on page come from PostHog's $pageleave; heatmaps show where people click and hover. Mailto values are stored as mailto: plus the subject, never the address. navigation.instant is off, so one delegated listener per full page load is enough. - EU cloud. The project key is a public, write-only browser key. - Loader stub: PostHog's official snippet (posthog.com/docs/libraries/js). #}
